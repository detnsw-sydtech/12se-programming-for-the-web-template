# Glossary  
### Programming for the Web – Software Engineering Stage 6 (Year 12)

This glossary explains key terms you will encounter throughout the unit. Use it as a reference while developing your Progressive Web App (PWA).

---

## **A**

**Accessibility**  
Designing software so it can be used by people with diverse abilities, including visual, auditory, motor, or cognitive needs.

**Algorithm**  
A step‑by‑step set of instructions used to solve a problem or perform a task.

**API (Application Programming Interface)**  
A set of rules that allows different software systems to communicate.

---

## **B**

**Back‑end**  
The server‑side part of a web application that processes data, runs logic, and communicates with the database.

**Browser**  
Software used to access and display web pages (e.g., Chrome, Firefox, Edge).

---

## **C**

**Client–Server Model**  
A structure where the client (browser) requests data and the server responds.

**CSS (Cascading Style Sheets)**  
A language used to style and format HTML content.

**Catalogue**  
A structured collection of items stored in your database and displayed in your PWA.

---

## **D**

**Database**  
A structured system for storing and retrieving data.

**DOM (Document Object Model)**  
A representation of a webpage that JavaScript can interact with.

---

## **E**

**Express.js**  
A lightweight Node.js framework used to build web servers and handle routing.

---

## **F**

**Front‑end**  
The part of a web application that users see and interact with (HTML, CSS, JavaScript).

**Fetch API**  
A JavaScript interface used to request data from a server.

---

## **H**

**HTML (HyperText Markup Language)**  
The standard language used to structure content on the web.

**HTTP / HTTPS**  
Protocols used to transfer data between a browser and a server. HTTPS is the secure version.

---

## **J**

**JavaScript**  
A programming language used to add interactivity and dynamic behaviour to web pages.

**JSON (JavaScript Object Notation)**  
A lightweight data format used to store and exchange information between the front‑end and back‑end.

---

## **L**

**Lighthouse**  
A tool used to test performance, accessibility, and best practices of a web application.

---

## **M**

**Manifest File (`manifest.json`)**  
A file that defines how a PWA behaves when installed, including icons and display mode.

**Middleware**  
Functions in Express that process requests before they reach the final route handler.

---

## **N**

**Node.js**  
A JavaScript runtime that allows you to run JavaScript on the server.

---

## **P**

**PWA (Progressive Web App)**  
A web application that behaves like a native app, with offline support, caching, and installability.

---

## **R**

**Routing**  
The process of defining how a server responds to different URLs or requests.

---

## **S**

**SQL (Structured Query Language)**  
A language used to create, modify, and query databases.

**SQLite**  
A lightweight, file‑based database used in this unit.

**Service Worker**  
A script that runs in the background of a PWA to enable caching and offline functionality.

---

## **U**

**UI (User Interface)**  
The visual elements of a software application.

**UX (User Experience)**  
How users feel when interacting with a software application.
